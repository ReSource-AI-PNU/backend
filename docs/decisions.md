# 조건 변경 재탐색 구현 결정

## AI 산출물에서 바로잡은 것

| 발견 | 수정 | 검증 |
|---|---|---|
| 업체 프로필이 바뀌기만 하면 영향 없는 변경도 새 진단을 만들 수 있었다 | 기존 agreedTerms와 현재 `_vendor_terms`를 대조해 배정한 폐기물·수거 조건에 영향받는 변경만 감지 | 기존 vendor terms 회귀 시험과 새 무관 변경 시험 |
| 새 비교 적용과 일반 업체 변경을 같은 승인 차단으로 다뤄 기존 수동 재협상까지 막았다 | 비교 token으로 적용한 대안만 이전 안을 대체하도록 차단. 업체 변경은 기존 근거·합의 검증을 유지 | 기존 수동 재협상·승인 회귀 시험 |
| 공통 API 호출이 별도 업체 A2A 수신에서도 회사 재탐색 큐를 실행했다 | 업체 메시지 수신은 큐 실행 대상에서 제외 | vendor_service 전체 시험 |
| 새 API 경로와 stale 오류가 계약 문서에 빠졌다 | 세 경로·오류 코드·재실행 정책을 명시 | API wiring 및 contract docs 시험 |
| 비교 수거 횟수가 업체 조건을 임의로 덮어쓸 위험 | 업체가 선언한 수거 횟수와 최소 횟수를 모두 만족하는 후보만 비교. 업체 프로필은 수정하지 않음 | 미리보기 원본 보존 및 수거 제한 시험 |

Jev와 새 모델·패키지는 추가하지 않는다. 기존 숫자 근거·판단 도구·실행 잠금·양쪽 승인 구조를 사용한다.

# 설문 후속 결정

| 결정 | 근거 | 검증 | 남은 제한 |
|---|---|---|---|
| 공개 범위를 단일 가격과 분리하고 거래별로 담당자가 좁힌다 | 처리업체 응답의 범위 공개 조건, 사용자 승인 | tests/v3/test_survey.py | 실제 업체 자료 검증 필요 |
| 단일 가격은 재질·품질·운반 확인 후 상대가 수락해야 기존 진단에 쓴다 | 범위의 중간값을 임의로 확정하지 않음 | 범위 좁힘·확인·수락·기존 진단 통합 | 기존 양쪽 승인과 허가 확인은 별도로 계속 필요 |
| 거리·차량 기준은 명시적으로 선택한다 | 수거 최소 기준 응답 | 물량 기준 해제·차량 초과 경계 | 실제 노선 경유지는 현재 앱 내 확정 방문만 |
| 사진 공유는 선택한 문의 상대에게만 | 방문 전 품질 확인 요구 | 비공개·공유·취소·다른 업체 차단 | 앱 밖의 업체에는 별도 발송하지 않음 |
| 중량 기록과 품질 측정 CSV를 분리한다 | 계량 기록만 있는 공장도 입력 가능해야 함 | 월별 합산·같은 파일 재업로드·중복 번호 | 계량번호가 없는 같은 날 같은 무게는 같은 기록으로 묶이므로 서로 다른 반입은 번호 필요 |

## AI 산출물에서 바로잡은 것

| 항목 | 수정 | 확인 |
|---|---|---|
| 공개 범위를 문서에서 등록할 때 단일가를 요구함 | 명시적으로 선택한 상·하한을 그대로 저장 | 문서 범위 등록 검사 |
| 업체 조건이 바뀐 뒤 과거 수락 가격을 재사용할 가능성 | 자료·기준 지문을 대조하고 기존 승인도 차단 | 변경 조건·기존 합의 검사 |
| 조회 응답에 내부 조건 지문이 포함됨 | 외부 응답과 공유 계산 근거에서 제거 | 공개 근거·정보 경계 검사 |
