# 조건 변경 재탐색 구현 결정

## AI 산출물에서 바로잡은 것

| 발견 | 수정 | 검증 |
|---|---|---|
| 업체 프로필이 바뀌기만 하면 영향 없는 변경도 새 진단을 만들 수 있었다 | 기존 agreedTerms와 현재 `_vendor_terms`를 대조해 배정한 폐기물·수거 조건에 영향받는 변경만 감지 | 기존 vendor terms 회귀 시험과 새 무관 변경 시험 |
| 새 비교 적용과 일반 업체 변경을 같은 승인 차단으로 다뤄 기존 수동 재협상까지 막았다 | 비교 token으로 적용한 대안만 이전 안을 대체하도록 차단. 업체 변경은 기존 근거·합의 검증을 유지 | 기존 수동 재협상·승인 회귀 시험 |
| 공통 API 호출이 별도 업체 A2A 수신에서도 회사 재탐색 큐를 실행했다 | 업체 메시지 수신은 큐 실행 대상에서 제외 | vendor_service 전체 시험 |
| 새 API 경로와 stale 오류가 계약 문서에 빠졌다 | 세 경로·오류 코드·재실행 정책을 명시 | API wiring 및 contract docs 시험 |
| 비교 수거 횟수가 업체 조건을 임의로 덮어쓸 위험 | 업체가 선언한 수거 횟수와 최소 횟수를 모두 만족하는 후보만 비교. 업체 프로필은 수정하지 않음 | 미리보기 원본 보존 및 수거 제한 시험 |

Jev와 새 모델·패키지는 추가하지 않는다. 기존 숫자 근거·판단 도구·실행 잠금·양쪽 승인 구조를 사용한다.
