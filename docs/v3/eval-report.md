## 4. 사례에 적어 둔 메모

- C09: 두 번째 호출이 수정 뒤의 입력이다. 금지 사항(수정 뒤 PP 단가 유지)은 두 번째 호출의 absentClaims로 본다. 이전 승인 상태 유지와 과거 기록 덮어쓰기는 tests/v3/test_judge_fixed_cases.py가 계산 근거 ID와 판으로 확인한다.
- C12: 설계 판단(확정): 사진 추정 오염 비율과 담당자가 답한 수분은 매입 기준 상한 안이어도 충족을 '확정'으로 두지 않는다. 측정값이 없으면 조건부이고 '반입 검수에서 확인' 조건이 붙는다(추정 물량과 같은 원칙).
- C33: 설계 판단(확정): 최소 물량에 못 미쳐 '기존 노선에 묶어 수거'하는 조건이 붙는 답은 offer가 아니라 conditional로 온다. 그 제안은 배정되지 않고 대안으로만 남는다.
- C48: 설계 판단(확정): 주입이 탐지돼 합의한 대화가 handoff로 넘어가면 그 대화의 배정을 결과 한 장에서 빼고(그 흐름은 확인 필요), 그 업체를 빼고 최적안을 다시 계산한다. 승인을 기다리는 다른 대화가 없으면 진단은 승인 대기에서 벗어난다(idle).

## 5. 모델 형식 준수 시험

## 6. 근거 충실도 (Foundry 평가)

- 평가 입력: 사례의 실행 기록에서 수치나 조항을 인용한 글 91행(메시지 89, 문서 2)을 만들 수 있다 (`python3 -m app.v3.eval.foundry_eval --out eval-groundedness.jsonl`).
- 결과: 미측정. `scripts/v3/eval/run_foundry_eval.py`는 Azure AI Evaluation SDK와 Foundry 모델 배포가 있어야 돌고, 이 저장소에서는 돌려 보지 못했다.

## 7. 미측정 항목

- 형식 준수 시험: foundry (이 저장소에서는 실제 모델에 연결하지 않았습니다.)
- 형식 준수 시험: ollama (이 저장소에서는 실제 모델에 연결하지 않았습니다.)
- 근거 충실도(Foundry 평가 groundedness)
- 실제 모델로 돌린 사례 판정 일치율과 검증기 통과율(이 리포트의 사례는 규칙 정책으로 돌았다)
- 전문가 검토(사례의 기대값은 모두 초안이다)

## 8. 다시 만들기

```bash
python3 -m app.v3.eval.report --out docs/v3/eval-report.md
# 실제 모델과 Foundry 평가 결과를 넣으려면
python3 -m app.v3.eval.format_compliance --provider foundry --out foundry.json
python3 -m app.v3.eval.format_compliance --provider ollama --model <모델> --out ollama.json
python3 -m app.v3.eval.foundry_eval --out eval-groundedness.jsonl
python3 scripts/v3/eval/run_foundry_eval.py --data eval-groundedness.jsonl --out groundedness.json
python3 -m app.v3.eval.report --out docs/v3/eval-report.md \
  --compliance foundry.json ollama.json --groundedness groundedness.json
```
