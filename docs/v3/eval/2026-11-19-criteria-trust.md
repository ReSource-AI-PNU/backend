# 매입 기준표 판독: 신뢰성·현장 적용성 감점 대응 근거 (2026-11-19)

이 문서는 매입 기준표 판독에서 지적된 신뢰성·현장 적용성 문제가 어떤 증거로 해소됐는지 남긴다. 숫자는 모두 이 폴더의 원본 JSON에서 왔다. 실제 모델 호출과 모의 응답(가짜 판독기)은 맨 아래 "증거의 종류"에서 나눠 적었다.

## 감점의 원인(재현된 문제)

backend `dd93727`의 `app/v3/intake/documents.py`는 Document Intelligence가 돌려준 표에서 첫 행을 머리글로 보고, 머리글 낱말 사전으로 열을 찾았다.

- **현장 적용성:** 글자는 읽혀도 표 구조가 없거나(문장형 견적서), 제목 행이 첫 행을 차지하면 매입 기준이 0건으로 나왔다. 업체마다 양식이 다르다는 현장 조건에서 기능이 동작하지 않았다.
- **신뢰성:** 범위 단가 "300~400원/kg"을 300원/kg으로, 최소 물량 "1톤/월"을 1kg/월로 경고 없이 읽었다. 틀린 값이 그대로 단일 견적에 쓰일 수 있었고, 값마다 문서 원문과 쪽이 붙지 않아 검토할 수도 없었다.

## 바꾼 것과 그 증거

| 감점 근거 | 바꾼 것 | 증거 |
|---|---|---|
| 양식이 달라지면 0건 | 매입 기준표는 모델(Foundry gpt-5-mini)이 쪽 그림과 Document Intelligence의 쪽별 글·표 구조(병합 칸 HTML)를 함께 읽는다. 머리글 사전에 기대지 않는다 | 시험 PDF 11종 × 3회 = 33회 **통과 33/33** [95% Wilson 0.896, 1.000], 칸 정확도 **576/576** [0.993, 1.000] (`2026-11-19-criteria-pdf-v2.json`). 열 이름·순서 변경, 제목 행 + 두 줄 머리글, 병합 칸, 각주에만 있는 단위, 2쪽에 걸친 26행 표, 스캔본(글자층 없음), 격자선 없는 문장형 견적서가 모두 통과했다 |
| 같은 뜻인데 문서마다 값이 다를 수 있음 | 모델은 글자를 그대로 옮기고, 숫자 읽기·단위 환산은 코드(`criteria_llm.normalize`)가 한다 | 같은 PP 조건을 양식만 바꿔 적은 01~08번 24회차에서 PP A등급 행이 **모두 같은 값**(kg당 320원 매입, 월 1,000kg, 이물 3%, 수분 5%, 수거비 포함)이었다(`summary.sameMeaning.identical = true`) |
| 300~400원/kg → 300원/kg | 범위·협의·단위 미상·돈의 방향 불명·회당 물량은 값을 비우고 확인 사유를 단다. 범위는 두 끝을 후보로만 준다 | 09번 3/3: 범위 단가는 값 없음 + 후보 [300, 400], 회당 1톤은 월 물량으로 바꾸지 않음. 실제 화면에서 이 줄은 처음에 고를 수 없고 "고른 0줄 저장"이 꺼져 있었다(`2026-11-19-criteria-e2e.json`의 `rangeDocument`) |
| 300을 넣어도 문서 값처럼 저장될 수 있음 | 서버가 판독 초안(값·원문·쪽)을 보관하고, 저장 요청은 초안 ID와 행 ID만 가리킨다. 어느 값을 고쳤는지와 근거 발췌는 서버가 초안과 대조해 정한다(`verify_row`) | 담당자가 "300원으로"를 눌러 저장한 값은 **human 근거**로 남았다: "담당자가 적은 값: 300원/kg (문서 원문: 300~400원/kg · … · 1쪽)", 읽은 값 없음, 확인 사유 "단가가 범위로 적혀 있습니다". 화면 대신 API로 "고치지 않음"과 가짜 원문을 보내도 doc 근거가 생기지 않는다(`test_a_range_price_is_never_saved_as_a_document_value`) |
| 1톤/월 → 1kg/월 | 단위 환산은 코드가 한다: 톤 → ×1,000kg, 원/톤 → ÷1,000. 단위를 칸·머리글·각주에서 찾지 못하면 확인 대상이다 | 02번(원/톤·톤 단위) 실제 화면: "320,000원 → kg당 320원 · 1톤 → 월 1,000kg"을 보이고 doc 근거 15건으로 저장했다. 판독 모델 없이 표 머리글로만 읽는 길(규칙 판독)도 같은 코드를 거쳐 1톤/월을 1,000kg/월로 읽는다 |
| 값의 출처를 확인할 수 없음 | 값마다 문서 원문·쪽·단위를 찾은 곳(각주)·환산을 붙이고, 각주·공통 조건은 적용되는 줄에 잇는다 | 저장한 근거의 발췌 예: "320,000원 → kg당 320원 · “톤당 매입 가” · 1쪽". 근거 meta에 초안 ID, 읽은 값(aiValue), 확인 사유가 남는다 |
| 모델이 없거나 실패하면 예전 경로로 조용히 틀림 | 판독 모델이 없으면 규칙 판독이 같은 초안 모양과 같은 검증을 쓴다. 확신이 없으면(돈의 방향, 월 기준) 비워 둔다 | 규칙 판독 11종(실제 Document Intelligence): 통과 9/11 [0.523, 0.949], **틀린 값 0칸**, 칸 179/192. 문장형 견적서는 "매입 조건 없음"으로 담당자에게 넘겼다(`2026-11-19-criteria-rules.json`) |
| 실패와 "읽었지만 없음"이 섞임 | 깨진 파일(422 `DOCUMENT_UNREADABLE`), 문서 읽기 서비스 실패(502 `DOCUMENT_FAILED`), AI 판독 실패(`model_failed`), 매입 조건 없음(`not_found`)을 따로 돌려주고 화면 문장도 다르다 | 실제 호출: 깨진 PDF → "이 파일을 열지 못했습니다…", 틀린 모델 키 → "AI가 지금 문서를 읽을 수 없는 상태입니다", 회사 소개서 → "매입 단가나 처리비 조건을 찾지 못했습니다"(`failureKinds`, `screens`) |
| 확인하지 않은 값이 탐색에 쓰임 | 업로드는 초안만 만든다. 담당자가 고른 줄을 저장해야 업체 프로필이 된다. 문서 안전 검사(Prompt Shields)와 판독기의 지시문 탐지는 그대로다 | 11번(숨긴 지시문) 3/3 막힘. 업로드 직후 업체 프로필의 매입 기준은 비어 있다(`test_upload_returns_a_draft_and_nothing_is_saved_yet`) |
| 저장한 값이 실제 판단에 쓰이는지 | 저장한 기준이 새 탐색의 단가·최소 물량 판정에 쓰인다 | 실제 화면, 다른 조건이 같은 두 배출 기업: **999kg**은 최소 물량 검사 "합친 물량이 최소 물량에 못 미칩니다"(합친 월 물량 999, 최소 물량 1,000, 상태값 conditional)로 이 업체에 배정되지 않았고, **1,000kg**은 "met"으로 kg당 320원(문서 근거) 합의·배정됐다(`search`) |

## 모델 입력 방식을 고른 근거

연결된 Foundry 배포는 `gpt-5-mini`(2025-08-07)와 `text-embedding-3-small` 둘이다. gpt-5-mini에 같은 질문을 PDF 파일 직접 입력(API 버전 2024-10-21, 2025-04-01-preview, v1)과 쪽 그림 입력(144dpi PNG)으로 보냈다(`2026-11-19-criteria-inputs.json`).

- 두 방식 모두 200으로 답했다. 글자층이 있는 01번에서 PDF 직접 입력의 입력 토큰은 569개(쪽 그림 1,044개)로, 글자층 위주로 읽는 것으로 보인다.
- 스캔본 07번(병합 칸)에서 PDF 직접 입력 세 번 가운데 한 번은 최소 물량을 "(빈칸)"으로 답했다. 쪽 그림 입력은 맞게 답했다(각 1회라 차이를 일반화하지는 않는다).
- 그래서 기본 입력은 쪽 그림(코드가 쪽 번호·해상도를 정하고, 글·표 구조를 보조로 함께 보냄)이고, 쪽을 그리지 못한 PDF만 파일 그대로 보낸다. 그림을 받지 않는 모델이면 글·표 구조만으로 한 번 더 읽는다.

## 증거의 종류

| 종류 | 무엇 | 모델 |
|---|---|---|
| 실제 호출 | 입력 방식 확인(`criteria-inputs`), 판독 평가 33회(`criteria-pdf-v2`), 실패 구분(`criteria-e2e.failureKinds`), 실제 화면 점검(`criteria-e2e`) | Foundry gpt-5-mini(추론 강도 low, 구조화 출력), Document Intelligence prebuilt-layout, Prompt Shields |
| 실제 호출, 모델 없음 | 규칙 판독 평가(`criteria-rules`) | Document Intelligence, Prompt Shields만 |
| 모의 응답 | `tests/v3/test_criteria_llm.py` 80개(가짜 판독기 `FakeReader`, 가짜 Document Intelligence). 프런트 `tests/criteria.test.ts`는 앞서 실제 백엔드가 시험 PDF를 실제 AI로 읽은 응답을 예시 데이터로 쓴다 | 없음 |

실제 화면 점검은 로컬 백엔드·프런트를 운영과 같은 Azure 리소스에 붙여 돌렸다. 배포한 VM에서는 돌리지 않았다.

## 재현 방법

```sh
# Azure 키는 Key Vault에서 읽는다(infra/vm/deploy-vm.sh와 같은 이름)
export V3_LLM=foundry FOUNDRY_ENDPOINT=… FOUNDRY_DEPLOYMENT=gpt-5-mini FOUNDRY_API_KEY=…
export AZURE_DOCUMENT_INTELLIGENCE_ENDPOINT=… AZURE_DOCUMENT_INTELLIGENCE_API_KEY=…
export AZURE_CONTENT_SAFETY_ENDPOINT=… AZURE_CONTENT_SAFETY_API_KEY=…

uv run python -m scripts.v3.eval.criteria_pdf --runs 3 --out docs/v3/eval/2026-11-19-criteria-pdf-v2.json
uv run python -m scripts.v3.eval.criteria_pdf --reader rules --runs 1 --out docs/v3/eval/2026-11-19-criteria-rules.json
uv run pytest tests/v3/test_criteria_llm.py   # 모의 응답 80개
```

화면 점검은 `V3_AUTH=bff`로 백엔드를, 같은 BFF 키로 프런트(`NEXT_PUBLIC_API_BASE=/api/v3`로 빌드)를 띄운 뒤 업체로 허가증과 `02_reordered_units.pdf`를 올려 저장하고, 배출 기업 둘(PP 분쇄, 월 999kg · 1,000kg, 현행 혼합 소각 kg당 150원)로 "받아 줄 곳 찾기"를 눌렀다. 범위 단가는 `09_ambiguous.pdf`로 확인했다.

## 남은 한계

- 시험 문서는 직접 만든 가상 PDF 11종이다. 실제 업체 양식(손글씨, 휴대폰 촬영본)으로는 재지 않았다.
- 최소 물량에 못 미치는 경우의 상태값은 "미충족"이 아니라 "조건부"다(업체가 기존 노선에 묶어 받을 수 있는지 묻는 여지를 남긴 기존 판정 규칙). 배정에서는 빠진다.
- 판독 시간은 중앙값 27.1초이고 26행 2쪽 문서는 59~80초다. 출력 토큰이 대부분이다.
- 첫 화면 점검 회차에서 모델이 형태를 "사출 스크 랩"처럼 글자 인식의 띄어쓰기대로 옮긴 적이 있다. 값에는 영향이 없지만 담당자가 고칠 수 있게 형태 칸은 검토 화면에서 고칠 수 있다.
- 서버가 보관한 판독 초안은 조직을 지울 때만 지운다. 보관 기한은 아직 없다.
- 규칙 판독은 모델이 없을 때를 위한 길이다. 문장형 견적서는 읽지 못하고, 돈의 방향이 머리글·제목에 없으면 비워 둔다.
