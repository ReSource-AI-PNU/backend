# C 트랙 PP 검증 사례 v0.1

작성일: 2026-11-13
상태: 구현 전 제품·기능 검증 기준 초안. 현장 또는 처리업체 검증 결과가 아니다.

## 확정 범위

한 화면 입력폼 → 입력 요약·부족 정보 → 추가 질문 묶음당 최대 3개, 검토당 최대 2묶음 → 근거 대조 → 검토 요약·자원 명세·업체 문의서 초안.
사용자 문서 업로드, 실제 발송, 법적 분류·업체 수용 보증, 실제 운임 예측은 제외한다.
지원 재질은 PP. 다른 재질을 PP 기준으로 처리하지 않는다.
질문은 필요한 수만 생성한다. 모름은 유효한 답이며 새 정보 없이 반복 질문하지 않는다.
질문 수 제한은 테스트 가능한 1차 제품 정책이며 이후 사용성 검증으로 조정할 수 있다.

## 공통 입력·결과 정책

재질·형태·발생 과정·혼입 상태·물량·지역은 미응답과 명시적 모름을 구분한다.
사용자가 확인한 진술은 사용자 확인값이지 독립 검증된 사실이 아니다.
물량은 값·단위·기간·측정/추정을 함께 보존한다. 음수와 비유한 값은 입력 오류로 처리하고, 0은 수량 계산 보류로 처리한다.
금액을 C가 계산하지 않는다. 단가 조회·경제 효과 계산은 B/D와의 계약에 따라 연결한다.
질문할 사항이 없는 사례에서는 0개 질문으로 결과를 만든다.
입력을 수정하면 변경 이력과 버전을 남기고 종속 검토·문서의 재검토 필요 상태를 표시한다.
최대 질문 종료 후에도 미확인 사항을 명시한 부분 초안을 생성할 수 있다.

## 사례 10건

### C01 가공 전 PP 사출 불량품
- 가상 입력: 부산, 생산 중 발생, 월 500kg 추정, 가공 전, PP는 담당자 판단, 혼입은 미응답.
- 기대 질문 1묶음: 재질 판단 근거의 구체 내용, 다른 재질·금속 등 혼입 여부. 이미 입력한 가공 전 여부는 재질문하지 않는다.
- 예시 답변: 원자재 표기에서 PP 확인, 금속 인서트가 붙어 있음.
- 근거: E02, E06.
- 기대 결과: 원자재 표기와 폐기물 전체의 조성을 구분. 가공 전·금속 혼입으로 조사 압축품과 차이가 있음을 표시. 분리·반입 형태와 매입 조건을 업체 질문으로 작성.
- 금지: 압축품 가격 × 500kg을 실제 매각액으로 확정, 재활용 가능 보증, 임의 혼입 비율.

### C02 PP 압축품이나 품질·거래 단계 불명
- 가상 입력: 부산, PP는 사용자 확인, 선별·압축, 월 500kg 측정, 색상·혼입 상태는 모름, 발생 과정은 생산 중.
- 기대 질문: 현재 판매·인도 단계 확인, 알고 있는 선별 상태 확인. 이미 모름인 오염 수치를 다시 요구하지 않는다.
- 근거: E02, E05, E06.
- 기대 결과: 관련 항목은 PP 압축. 조사 기준이 잡색·생활계 혼합 및 가공업체 판매 단계라는 점을 설명하고 공장 자원과의 직접 비교는 미확정으로 표시.
- 금지: 압축 상태 하나만으로 조사 품질 일치나 실제 가격 적용 가능을 확정.

### C03 세척·파쇄한 PP
- 가상 입력: PP는 사용자 확인, 세척·파쇄, 생산 중 발생, 월 500kg 측정, 타 재질 없음으로 파악, 부산.
- 기대 질문: 파쇄 후 상태·색상·거래 단계 중 아직 필요한 확인만 최대 3개. 세척 여부를 중복 질문하지 않는다.
- 근거: E03, E06.
- 기대 결과: 플레이크가 관련 항목이며 압축품·펠렛과 구분. 산업계 입력과 생활계 혼합 조사 품질의 차이를 표시.
- 금지: 분쇄만으로 조사 기준 일치, 가공비·수율 없이 순이익 확정.

### C04 PP 펠렛, 조사 조건 진술이 모두 있는 경우
- 가상 입력: 부산, 월 500kg 측정, 세척 후 용융·압출, 잡색·생활계 혼합, 제품 제조사 납품 단계라고 사용자가 확인.
- 기대 질문: 필요한 정보가 충족됐다면 추가 질문 없음.
- 근거: E04, E05, E06.
- 기대 결과: 사용자 진술과 조사 조건을 항목별 대조해 참고 항목을 제시. 사실 검증·거래가격 보증과 구분해 출처·시점을 표시.
- 금지: 실제 품질 인증, 현재 시세·견적이라고 표현, 운임 포함으로 설명.

### C05 재질을 추정한 경우
- 가상 입력: 사출 불량품, 재질 PP 추정, 부산, 가공 전, 월 500kg 추정.
- 기대 질문: PP 판단 근거와 확인 가능한 자료 존재 여부. 예시 답변은 모름.
- 근거: E02, E06. 문서가 사용자 물질의 재질을 판별해주지는 않음.
- 기대 결과: PP로 가정한 설명임을 표시. 재질 미확인을 명세와 업체 문의서에 유지하고 반복 질문 종료.
- 금지: 외관·용도만으로 PP 확정, 모델의 확신을 사용자 확인으로 기록.

### C06 형태를 모르는 경우
- 가상 입력: PP는 사용자 확인, 형태 모름, 부산, 월 500kg 측정.
- 입력폼 계약: 가공 전/압축/세척·파쇄/펠렛과 짧은 설명 및 모름 선택지를 최초 입력 시 제공한다.
- 기대 질문: 설명을 보고 모름을 선택했다면 형태 설명을 반복하지 않는다. 새 관련 정보와 재질문 근거가 생긴 경우에만 다시 묻는다.
- 근거: E02, E03, E04, E06.
- 기대 결과: 한 형태를 임의 선택하지 않고 형식 차이와 확인할 사항을 설명. 명세의 형태는 미확인.
- 금지: 가장 비싼 펠렛 가격 선택, 형태별 차이를 작업만 하면 얻는 순이익으로 설명.

### C07 다른 재질·금속이 섞인 경우
- 가상 입력: PP 사출품에 ABS·금속 인서트 혼입, 가공 전, 부산, 월 500kg 추정.
- 기대 질문: 분리 상태·구분 보관 가능 여부 중 직원이 답할 수 있는 항목만 질문. 분리 가능은 업체의 수용 가능과 구분.
- 근거: E02, E06.
- 기대 결과: 조사 품질 기준과 혼입 상태를 대조하고 실제 수용·전처리 조건 확인 필요로 남김.
- 금지: 이 자료만으로 ABS 혼합은 열분해, 금속 포함은 소각이라고 확정하거나 폐기물 유해성 판정.

### C08 발생량을 모르는 경우
- 가상 입력: PP 압축, 부산, 월 발생량 모름. 다른 정보는 사용자 진술.
- 기대 질문: 기록을 확인할 수 있는지 한 번 묻거나, 이미 모름이 확정됐다면 측정·기록 확보를 다음 행동으로 제시.
- 근거: E01, E02, E05.
- 기대 결과: 품목 기준 설명은 계속 제공. 수량·총액은 미확인으로 두고 부분 명세 생성.
- 금지: 0kg 대체, 사진으로 월 중량 추정, 임의 발생량으로 총액 계산.

### C09 답변 수정으로 재질·물량이 달라진 경우
- 초기 입력: PP, 월 500kg 추정, 부산, 가공 전.
- 수정 이벤트: 재질을 PE로 수정하고 물량을 800kg 측정으로 정정.
- 기대 질문: 명시적 수정은 새 값으로 반영하며 같은 사실을 무조건 다시 묻지 않음. 수정인지 추가 주장인지 모호할 때만 확인.
- 근거: PP 지원 범위는 제품 정책. E02~E04를 PE에 적용하지 않음.
- 기대 결과: 최신 자원은 PE 지원 범위 밖으로 안내. 이전 PP 검토·초안은 오래된 버전으로 표시. 800kg과 측정 상태 및 변경 이력 보존.
- 금지: PP 가격·판정을 유지, 이전 승인 상태 유지, 과거 기록 덮어쓰기.

### C10 실제 운송비를 물어보는 경우
- 가상 입력: 부산 PP 압축품, 사용자 질문 '이걸 가져가는 실제 운송비는 얼마인가요?'
- 기대 질문: 운임을 찾겠다는 이유로 끝없는 추가 질문을 하지 않음. 견적 존재 여부 확인은 필요할 때 한 번만.
- 근거: E01, E05.
- 기대 결과: 자료 가격은 물류비 제외이고 이 PDF로 실제 운임을 알 수 없음을 설명. 업체 문의서에 차량·회차·상하차·포함 항목 등 확인 질문 제안(제품 제안이며 PDF 법정 요구사항으로 인용하지 않음).
- 금지: 가상 운임을 실제 견적으로 제시, 거리만으로 확정 운임 생성, 조사 가격에 운임 포함으로 답변.

## 공통 검증 항목

- 질문 묶음당 3개 이하, 검토당 최대 2묶음. 필요 없으면 즉시 결과 생성.
- 모름·미응답·추정·사용자 확인을 구분.
- 사용자 진술과 문서 근거를 별도 표시.
- 근거 ID와 페이지가 실제 검색 결과에 존재하고 설명을 지지하는지 확인.
- 원문에 없는 수치·법적 결론·업체 수용 조건을 생성하지 않음.
- 남은 불확실성은 초안에서 지워지지 않음.
- 자료 기준월은 2026-08이며 현재·최신 가격으로 표시하지 않음.
- 음수·비유한 수량은 입력 오류. 이 항목은 사례 10건과 별도 입력 검증 테스트로 구현.

## 다음 구현 작업에 전달할 범위

먼저 제품 입력·질문·검토 결과의 계약과 가상 fixture를 작성한다. Azure·RAG·화면은 별도 단계로 연결한다. 기존 공통 스키마와 세션 계약을 확인해 재사용 가능성을 판단하고, 기존 API 의미를 바꾸지 않는다. 이 문서는 테스트 기대값의 초안이지 코드가 이미 구현됐다는 뜻이 아니다.
