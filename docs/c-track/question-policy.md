# C 트랙 질문 선택 정책 v0.1

상태: C 질문 모듈 정책 (2026-11-13 리뷰 수정 반영)
작성일: 2026-11-13
관련 검증: ./pp-validation-cases.md

## 합의된 사용자 흐름

한 화면 입력폼 → 입력 요약·부족 정보 → 관련 질문 최대 3개씩 최대 2묶음 → 공식 자료 대조 → 검토 요약 → 명세·업체 문의서 초안.
첫 지원 재질은 PP. 문서 업로드·실제 발송·법적 적합성 확정은 제외한다.

## 역할

코드는 입력 상태, 질문 후보, 반복 금지, 질문 수·횟수 제한, 허용 항목과 응답 형식을 통제한다.
Azure 모델은 허용된 후보 안에서 관련 질문을 선택·표현하고 검색 근거를 설명한다.
모델은 필드를 새로 만들거나 모르는 값을 확정할 권한이 없다.

## 우선순위

1. 재질과 확인 근거
2. 현재 형태·혼입 상태
3. 지역·발생량

기준 설명과 부분 명세 작성은 발생량이 없어도 계속한다. 금액 계산은 B/D의 별도 기능이며 수량 누락 시 보류한다.
우선순위는 기본값이며, 한 답변이 다른 항목을 무효화하거나 PP 범위를 벗어나면 우선 해당 의존성을 처리한다.

## 상태 모델의 의미

구현 시 기존 공통 계약을 먼저 확인하고 아래 의미가 보존되는 최소 모델을 사용한다.
- 미응답: 아직 질문·응답하지 않은 항목.
- 모름: 사용자가 알 수 없다고 명시한 항목.
- 값 있음: 사용자가 제공한 값. 추정·확인 근거를 별도 보존한다.
- 충돌: 서로 양립할 수 없는 주장이 있으며 명시적 수정인지 불명확한 상태.
사용자 확인은 독립 검증 또는 품질 인증이 아니다. 추정값은 사용자 재확인만으로 실측값이 되지 않는다.

## 질문 처리

1. 최신 입력과 답변을 정규화한다.
2. 코드가 미응답·충돌·필요한 근거 항목으로 질문 후보를 만든다.
3. 새 정보 없이 명시적 모름 항목을 후보로 되돌리지 않는다.
4. 후보가 없거나 2묶음 한도에 도달하면 질문을 끝낸다.
5. 관련 후보 전체와 우선순위 및 상태 스냅샷을 모델 선택에 제공한다. 선택은 최대 3개다.
6. 모델은 후보 ID, 질문, 필요한 이유, 답변 유형, 허용 선택지를 구조화해 반환한다.
7. 코드는 후보 ID·중복·질문 개수·선택지와 평가 스냅샷의 무결성을 검증한다. 입력이 변경되면 이전 선택은 거부한다.
8. 검증된 묶음을 사용자에게 실제 표시한 시점에 질문 횟수를 증가시킨다. 실패·재시도·단순 조회는 증가시키지 않는다.
9. 답변은 해당 질문·항목 ID와 연결한다. 이전 질문이 이미 해결됐다면 재질문하지 않는다.
10. 한도 종료 후 남은 사항은 미확인으로 부분 결과와 업체 질문에 남긴다.

질문 개수를 채우기 위해 불필요한 후보를 추가하지 않는다.
명시적 입력 수정은 최신 값으로 반영한다. 모순된 추가 주장일 때만 확인 질문을 제안한다.
변경 이력과 종속 결과의 재검토 필요 상태를 보존한다.

## 모델 오류 처리 — 구현 제안

모델 장애·출력 검증 실패 시, 코드가 같은 후보의 사전 정의 질문을 제시하는 폴백을 권장한다.
이 경우 규칙 기반 대체임을 호출 기록에 남기며 Azure 호출 성공으로 기록하지 않는다.
실제 구현 전에 사용자에게 폴백 정책을 확인할 수 있다. 무제한 재시도는 허용하지 않는다.

## PP 외 입력

첫 버전 지원 범위 밖으로 표시하고 PP 가격·판정을 적용하지 않는다.
확인된 사용자 입력을 보존하고, 필요하면 일반 문의용 부분 명세를 만든다.

## 필수 검증

- 후보가 5개여도 묶음은 3개 이하.
- 2묶음 후 추가 질문 없음.
- 이미 모름·해결한 항목의 새 정보 없는 반복 없음.
- 모델이 만든 미허용 ID·중복·변조된 선택지는 반영하지 않음.
- 재질·근거 → 형태·혼입 → 지역·물량의 기본 순서.
- 지역·물량 누락은 전체 설명·부분 명세를 막지 않음.
- PP→PE 수정은 PP 종속 결과를 재검토/지원 범위 밖으로 변경.
- 모델 호출 실패 시 상태·질문 횟수 오염 없음.

## 이번 구현의 경계

질문 정책·입출력·가상 fixture·테스트부터 만든다. Azure·RAG 연결 전에는 가짜 모델 실행을 실제 호출로 표시하지 않는다.
DB·세션 API·UI는 별도 작업이며 여기서는 상태 입력→다음 질문/종료 결과 반환 함수를 우선 작성한다.

## 입력폼·종료 계약 (리뷰 수정)

최초 입력폼은 형태 선택지와 짧은 설명을 함께 제공한다: 가공 전(가공되지 않은 상태), 압축(선별 후 압축), 세척·파쇄(세척하고 잘게 파쇄), 펠렛(용융·압출한 알갱이), 모름. 이 문서는 UI 계약이며 UI 구현은 별도다. 설명을 보고 모름을 선택하면 `status=unknown`, 값 없음으로 보존하고 새 관련 정보와 재질문 근거가 없으면 다시 묻지 않는다. 초기 모름과 질문에 대한 모름은 모두 답변 당시 항목 revision을 기준으로 삼는다. 새 정보 반영 시 기존 answered_revision을 보존하고 revision과 근거를 갱신한다.

대기 답변과 지원 범위를 먼저 확인한다. 후보가 없으면 `complete`는 질문 과정의 종료만 뜻하며 사실 검증을 의미하지 않는다. 후보가 남아 있지만 두 묶음 제한으로 진행할 수 없으면 `limit_reached`다. 모름과 건너뛴 미확인 항목은 유지한다. 표시 이력과 스냅샷은 순수 상태에만 포함하며 저장·동시성 보장은 후속 통합 범위다.
